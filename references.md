# References — every browser tool assessed, one verdict each

Read this before proposing a different tool: each entry holds the verdict and the reason, with upstream links. The live design stays in README.md; this file is the memory. Context for all of it: the agentic loop this pool serves is planner LLM → Jev-style decider → this browser executes; local decision models remove the paid decision API, this pool removes the local browser installs. Measurements and the long-form findings: [survey/2026-10-23.md](survey/2026-10-23.md).

## The pool: under revision

- **Steel self-host** ([steel-dev/steel-browser](https://github.com/steel-dev/steel-browser), Apache-2.0) — **verdict: not the pool.** Single-session by design: "Self-hosted Steel runs one browser session at a time and has no managed proxies, browser profiles, managed credentials, or CAPTCHA solving" (`steel-mcp-server/README.md:57`). Measured: three parallel sessions or three parallel `/v1/scrape` calls kill the process (`TargetCloseError`, 3 of 3), 5 GB image, no auth, `persistProfile` persists nothing, 434–566 MiB for one session. What it genuinely adds is a session API and anti-bot launch flags — both reproducible in Playwright, which is why [the equivalents are tabulated](survey/2026-10-23.md#playwright-equivalents). Revisit only if concurrency, auth and real profiles land. Self-host wiring for reference: [self-hosting guide](https://steel.dev/blog/self-hosting-steel-browser).
- **Playwright Chromium container, one per session** ([microsoft/playwright](https://github.com/microsoft/playwright), Apache-2.0) — **leading candidate, not yet adopted.** Official Playwright image, one container per session, recycled after each run, `storageState` per session, Steel's anti-bot flags copied across. Playwright supplies every session feature we used; the pool (lease, health, recycle-after-use, limits, reaping) is ours to write. Blocked on measurement, not on a decision.

## Read tier, escalation, other engines

- **Lightpanda** ([lightpanda-io/browser](https://github.com/lightpanda-io/browser), AGPL-3.0) — **a read tier, not the pool.** 224 MB image, ~45 MB RSS measured, clean text on server-rendered pages. But it refuses a `Mozilla` user-agent by design (`src/Config.zig:1740`), returns nothing for PDFs, and ships telemetry on by default. Revisit trigger: bulk read volume where 44 MB per page beats a Chromium container.
- **Camoufox** ([daijro/camoufox](https://github.com/daijro/camoufox), MPL-2.0) — **escalation, not the pool.** The best-maintained anti-detect engine, but Playwright drives it through Juggler only: no CDP, so it does not drop into this harness. Revisit trigger: a real source that blocks Chromium.
- **camofox-browser** ([jo-inc/camofox-browser](https://github.com/jo-inc/camofox-browser)) — **assessment pending.** A server wrapper around Camoufox: 4.08 GB image measured, a first cold load of a Cloudflare-fronted page hit the challenge and clean retries read the page. The survey has no section for it yet, so no verdict — the wrapper inherits Camoufox's no-CDP constraint until shown otherwise.

## Client layers: what drives the pool

- **Deterministic Playwright** ([microsoft/playwright](https://github.com/microsoft/playwright), Apache-2.0) — `playwright-core` client only, no browser download. Default for known-assertion gates: zero model latency, zero token cost.
- **Playwright MCP** ([microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp), Apache-2.0) — the MCP shape of that same connection: `--cdp-endpoint` at a pool endpoint, `--isolated` for a throwaway profile, `--storage-state` to restore one, `--port` for SSE. A client layer, never the server — the pool still owns sessions.
- **chrome-devtools-mcp** ([ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp), Apache-2.0) — already in use; `--browserUrl` aims it at a pool container, which is what a dev agent needs to inspect a live page. One container plus this is the whole dev-agent story — no session API.
- **Jev loop** (later) — planner LLM + ~300 ms typed decisions on DOM state for fast agentic flows. Blueprints: [jev-browser](https://github.com/Ying-Kai-Liao/jev-browser) (MCP tools, LLM plans, Jev decides, Playwright acts; 40/42 live tasks) and [jev-ego](https://github.com/romaluev/jev-ego) (same policy minus Playwright, warm-session numbers: observe 0.11 s, act 0.17–0.27 s). Reference policy: [jev-ultrafast](https://github.com/browser-use/jev-ultrafast). Project list (our fork): [awesome-jev](https://github.com/mihado/awesome-jev). Local decision models remove the paid API: [Laya](https://github.com/NandhaKishorM/laya) ([weights](https://huggingface.co/convaiinnovations/laya)) and [agent-jev](https://github.com/malevrigns/agent-jev) ([weights](https://huggingface.co/aimeigaoshou/agent-jev)), both Apache-2.0. Planner candidate: MiMo-V2.6-Flash ([weights](https://huggingface.co/XiaomiMiMo), MIT, $0.14/$0.28 per MTok) — endpoint compat still to verify at wire time.
- **midscene** (contender, [web-infra-dev/midscene](https://github.com/web-infra-dev/midscene), MIT) — vision-driven `aiAct`/`aiAssert` on an existing Playwright page: visual assertions and flows selectors can't reach (canvas, icon-only buttons, cross-origin iframes). Generative-VLM call per step, so slower and metered — scoped to where DOM fails. Published runs: AppControlBench 96.7%, 60 tasks for $0.59 on Doubao. Adopt after pricing one real gate run.

## Dev-machine complement (not the pool)

- **BrowserSkill** ([Tencent/BrowserSkill](https://github.com/Tencent/BrowserSkill), MIT) — drives your logged-in GUI browser from any shell-capable agent: separate Agent Window, tab borrowing with confirmation, human-in-loop for captchas and logins. For everything the headless pool structurally cannot do (SSO staging, personal accounts, captcha'd pages, look-at-what-I'm-seeing). Never a pool component: no login state, no human headless.
- **OpenCLI** ([jackwener/OpenCLI](https://github.com/jackwener/OpenCLI), Apache-2.0) — turns sites into commands by driving your own logged-in desktop Chrome through a browser-bridge extension and a local daemon. No headless or server mode, so it cannot be the pool; worth copying for CLI ergonomics (`--session`, JSON envelopes, adapter authoring) and nothing else.

## Rejected

- **Browserless self-host** ([browserless/browserless](https://github.com/browserless/browserless)) — SSPL-1.0 OR commercial, verified in its LICENSE: "…or in a continuous-integration system that's closed-source then you'll need to purchase a commercial license". That names our use case; unsafe for work use without a paid license.
- **HeadlessX** ([saifyxpro/HeadlessX](https://github.com/saifyxpro/HeadlessX)) — AGPL-3.0, and a scraping platform (dashboard + queue + Postgres + Redis), not a browser pipe: no raw-Playwright endpoint. Its Firefox engine (Camoufox) is being phased out for a Chrome fork in v2.5.
- **Stagehand** ([browserbase/stagehand](https://github.com/browserbase/stagehand)) — dropped entirely. API-compatible with Playwright and faster than cloud Playwright and naive agent loops, but every action is an LLM call: strictly slower than deterministic Playwright for gates. The Jev loop is the fast path for agentic browsing instead.
- **moli** ([lexmount/moli](https://github.com/lexmount/moli), Apache-2.0 OR MIT) — a real engine, eleven weeks old: no Docker image, one dominant contributor, 436 open issues, and two benchmark tables in its own README that cannot both be measuring the same thing. Revisit in six months, not before.
- **pinchtab** ([pinchtab/pinchtab](https://github.com/pinchtab/pinchtab)) — a Go CDP bridge claiming to be the pool we need, with no concurrency or isolation evidence behind the claim. The pool is the hard part; a claim is not evidence.
- **CloakBrowser** ([CloakHQ/CloakBrowser](https://github.com/CloakHQ/CloakBrowser)) — "87 source-level patches", "passes Turnstile", a downloaded Chromium binary behind a paid Pro tier, and an MIT badge that covers the wrapper at best. Unverifiable, and the licence on the binary is the licence that matters.
- **jev-openfast** ([samuelyossef/jev-openfast](https://github.com/samuelyossef/jev-openfast), MIT) — a one-person desktop beta with one star, testing Windows first, driving a real Chrome tab. Its DOM-snapshot-to-typed-action design is a note; it is not a dependency.
- **browser-use** ([browser-use/browser-use](https://github.com/browser-use/browser-use), 118k★) — the reference implementation of a Python agent loop. Useful to read, wrong language and wrong layer to depend on.
- **Skyvern** ([Skyvern-AI/skyvern](https://github.com/Skyvern-AI/skyvern), AGPL-3.0) — an agent platform (workflow engine, vision, queue), heavy and copyleft. Both disqualify it.
- **Crawl4AI** ([unclecode/crawl4ai](https://github.com/unclecode/crawl4ai), Apache-2.0) — extraction only, no sessions; only if bulk extraction becomes the job itself.
- **obscura** ([h4ckf0r0day/obscura](https://github.com/h4ckf0r0day/obscura)) — self-benchmarked at 29.7% task success. No.
- **Raw `--remote-debugging-port` Chrome** — no auth, no sessions, Playwright's lower-fidelity CDP caveats. Fallback only.
- **Firefox day one** — deferred. Gates verify our own work; if that changes, Playwright's own Firefox build through the same pattern.

## Fallbacks, never evaluated

- **Gotenberg** ([gotenberg/gotenberg](https://github.com/gotenberg/gotenberg)) — stateless screenshot/PDF API. Only if interaction needs turn out to be load-assert-screenshot and nothing more.
