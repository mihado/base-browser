# Browser server survey — 2026-10-23

Evidence behind the pool's design decisions. README.md holds the live decisions, references.md the verdict per tool; this file holds the measurements and the reasoning they came from. Nothing here is deployed.

Method: three source types a legal product must read — a federal rules site that gates on user-agent, a server-rendered state legislature site, a Cloudflare-fronted state code site — plus a 1,039-page federal PDF. Run locally, account-free, on one host, against the container images as tagged. Sizes, timings and failures below were measured here; release and star counts come from upstream metadata.

## Steel self-host is single-session by design

Upstream states it in the MCP server's README (`steel-mcp-server/README.md:57`): "Self-hosted Steel runs one browser session at a time and has no managed proxies, browser profiles, managed credentials, or CAPTCHA solving".

Measured in a clean container on one host:

| Check | Result |
| --- | --- |
| 3 sessions, sequential | 200, 200, 200 — all live |
| 3 sessions, parallel | process exits 1, `TargetCloseError` — 3 of 3 runs |
| 3 `/v1/scrape`, parallel, cold | 500 `CDPService has not been launched yet!` |
| 3 `/v1/scrape`, parallel, warm | connections dropped, process exits 1 |
| Image size | 5.00 GB |
| Memory, one session | 434–566 MiB |
| Auth | none — `/v1/scrape` returns 200 unauthenticated |
| `persistProfile: true` | accepted, no `profileId` in the response; the next session reads back empty state |

Sessions are multiplexed contexts inside one Chromium, so one bad target takes the API down with it: an unhandled `TargetCloseError` ends the process. Two years in, it is still a public beta — 14 commits in 90 days, quarterly releases, the last `v0.5.4-beta`.

### What it does add over plain Chromium

A REST session API (`POST /v1/sessions`, release, timeouts), `GET /v1/sessions/{id}/context` returning cookies and storage as JSON, a proxy per session with byte counters, quick actions (`/v1/scrape`, `/v1/screenshot`, `/v1/pdf`), extension loading, and a live viewer a human can watch or take over. None of Playwright MCP, chrome-devtools-mcp, Lightpanda or Moli gives you a shareable "here is the agent's screen" link.

## The anti-bot defaults worth copying

Steel fetched every page naive headless Chrome could not — the federal rules site's user-agent gate, the Cloudflare-fronted state code site — and the difference is launch flags, not magic: a mainstream Chrome user-agent string, `--disable-blink-features=AutomationControlled`, `ignoreDefaultArgs: ["--enable-automation"]`, and headful Chromium under Xvfb. One flag, `--user-agent`, reproduced the federal site result on plain Chrome.

Its fingerprint is still mediocre: `navigator.plugins.length = 0`, `navigator.mimeTypes.length = 0`, SwiftShader WebGL, and a timezone matching neither host nor target. Passing or failing a bot check on that stack is close to a coin flip — which is why the flag set is worth copying and the claims are not.

## Playwright equivalents

Checked against the Playwright docs. Everything Steel's session API does, Playwright does once you own the process:

| Steel feature | Playwright equivalent |
| --- | --- |
| CDP endpoint any client can drive | `chromium.launchServer()` → `wsEndpoint`, then `chromium.connect(wsEndpoint)`; client and server major/minor must match |
| Attach to an already-running Chromium | `chromium.connectOverCDP()` — Chromium-based browsers only |
| Session `/context` (cookies + storage as JSON) | `context.storageState()` to save; pass `storageState` to `newContext()` to restore |
| Proxy per session | `newContext({ proxy })` — per context, no server involved |
| `/v1/pdf` | `page.pdf()` — Chromium's print path (the only engine we run) |
| Extension loading | `launchPersistentContext()` plus `--load-extension` |
| Session API for MCP clients | Playwright MCP: `--port`, `--cdp-endpoint`, `--isolated`, `--storage-state` |
| Live viewer | Not built in. Choose: headful under Xvfb with a VNC view, a CDP screencast (`chrome://inspect` or `Page.startScreencast`), or video and trace recorded per context |

## The pool is the work, the session API is not

Steel's shape is right and its maturity is the problem. What the pool actually needs — lease a session, check it is healthy, recycle it after use, cap concurrency, reap what leaked — Steel does not provide; it provides a thin session API on top of exactly the Playwright calls in the table above. Once that API is a handful of Playwright calls, the hard part is unmoved: the orchestrator. So the choice is not "Steel or Playwright"; it is whether to own a small pool (lease, health, recycle-after-use, limits, reaping) and put a thin session API on it, or wait for a vendor to ship the pool. Today no vendor ships the pool.

That points at the leading candidate: the official Playwright Chromium image, one container per session, recycled after each run, `storageState` per session, Steel's launch flags copied across. The session API becomes our own small layer, and it is the only new code.

## Traps

- **Licences, read not inferred.** Browserless is SSPL-1.0 OR commercial, and its LICENSE names CI explicitly: "…or in a continuous-integration system that's closed-source then you'll need to purchase a commercial license". Lightpanda and Skyvern are AGPL-3.0, and Lightpanda ships telemetry on by default (`LIGHTPANDA_DISABLE_TELEMETRY=true` to turn it off). HeadlessX and nodriver are AGPL too.
- **Star inflation.** Several of the loudest repos in this topic were created in 2026 with 18k–32k stars and no shipped product; one engine is eleven weeks old, publishes two mutually inconsistent benchmark tables, and ships no Docker image. Stars measure marketing velocity here, not maturity.
- **"Passes every bot detection test."** A marketing claim, not a measurement — and a tool that wins that contest is also a tool that ignores the site's stated terms.
- **Cloud-only features sold as features.** Profiles, managed proxies and CAPTCHA solving are cloud in Steel and absent in self-host; the same pattern appears in the new engines, whose commercial tier sits behind the OSS one.
- **Unauthenticated browser APIs.** No tool in this class ships auth. An open browser API on the network is an open proxy with our IP and whatever cookies are in the container.
- **Image weight.** 5 GB for Steel against 224 MB for Lightpanda against a Chromium container; the per-image patch cadence is a standing cost, not one-off.

## API first, browser second

Some government sites block automation by policy and say so: their interstitial directs automated clients to the developer APIs instead. That is a product requirement, not an engineering obstacle — call the API where one exists, browse only the long tail. A stealthier browser is the wrong answer to a site that has published the right one, and it is a licensing question before it is a fingerprint question.

## What to measure next

One Playwright Chromium container per session: memory per session, cold-start and recycle cost, and the peak concurrency the VM can actually hold. Until that number exists, the Sizing section in README.md stays TBD.
